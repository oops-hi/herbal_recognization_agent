## 0. 一句话定位（开场）

**多模态中草药识别智能体**：本地 CNN（20 类果实种子类饮片细分类）+ 知识图谱（64 味）+ 云端 LLM/VLM 的**真智能体**——工具调用链由问题决定，而非代码决定。

## 1. 核心卖点（答辩三句话）

1. **真正的智能体**：识别→查药性→查禁忌→找方剂，调用链与次数由问题决定；不是「识别后 LLM 写段文案」的固定流水线。
2. **多模态在工具调用层融合**：图像模态（CNN 识别）+ 文本模态（用户提问）进入同一条手写 ReAct 推理链。
3. **合规边界**：不输出诊断 / 辨证 / 剂量 / 疗效；禁忌 = 知识展示；全部医学数据以《中国药典》2020 年版为准并带溯源。

## 3. 关键技术决策的论证（每一条都是应诉求）

### 3.1 为什么本地 CNN + 云端 LLM，而不是全云端 / 全本地
- 演示第 6 步「拔网线」场景：本地识别 + 图谱页**必须离线可用**，对话区降级但友好 → 本地模型是底座。
- 细分类（砂仁 vs 豆蔻）本地更准（实测），域外开放识别（是不是药材）云端 VLM 更强（实测）——**各管一头**。

### 3.2 为什么手写 ReAct 而不上 LangChain
可控（任务量小、能逐字节调试）、轻量（无 40+ 依赖）、**演示性**（SSE 时间轴让评委实时看到工具逐个触发——框架封装后反而难展示）。核心循环仅数十行。

### 3.3 为什么自研向量检索不用 ChromaDB
chromadb 1.5.9 拖 40+ 依赖（含 kubernetes / onnxruntime），代理下载不稳；自研 numpy 实现（归一化内积 + 多 query 同义词并集）674 条 16 秒入库，效果达标（20/20 命中）。

### 3.4 为什么 VLM 只在「域外拒绝」上有否决权（V2-A6 核心结论）
**闭集分类器没有「非药材」出口**：任何输入都被软 max 硬塞进 20 类之一，域外图照样给出高置信度（宠物实测最高 0.94）。这暴露了「堆训练数据治不了域外误判」——所以加云端开放词表 VLM 做第二通道，且**只有 non_herb 一票否决**：
- 域内细分类（砂仁/豆蔻→草豆蔻）qwen-vl-max 系统性弱于本地 → conflict 只挂黄徽章，保留本地结论（弱证据不能否决强证据）；
- 域外判定可靠 → 猫狗图 6/6 拒答，且能说出「疑似猫科动物/犬科动物」粗分类（纯展示，白名单限长/禁药名/禁知识词）。
- **两轮口径修订都是 26 张真实图评测校准的**（20 混淆对 + 6 宠物），不是拍脑袋。

### 3.5 为什么「堆训练数据」不能治域外高置信误判（已被问）
- 模型学到的是「20 类之间的分界」，不是「药材 vs 世界」；训练数据里没有「非药材类」。
- 继续灌饮片数据只让特征空间更内聚，域外置信度可能更高（softmax 对 OOD 系统过置信，学界已实证）。
- 加负类能救覆盖到的部分，但开放世界无穷尽，负类永远补不全；且全链路 20 类硬编码要联动改。
- **结论**：域内混淆（桃仁 recall 0.30）靠训练能改善；域外误判靠训练治不了 → 这是设计 VLM 二通道的动机。

### 3.6 医学数据工程与合规（最重要红线）
- 全部药性 / 方剂 / 禁忌条目以《中国药典》2020 年版为准，每条带 `source` 字段（《…》+年版）；
- **LLM 起草 ≠ 定稿**：2026-08-27 人工逐条核对（review_status），高危 8 味（附子/细辛/川乌/草乌/半夏/苦杏仁/桃仁/人参）双人复核；台账化（review_ledger）版本化管理，药典换版走重核机制；
- 「甘草+海藻」「人参+五灵脂」「硫黄+朴硝」三对为**歌诀有、药典未认定** → 前端必须分开展示两种依据；
- 输出侧五道闸门兜底（见 §4），剂量模板句式（「你应该用 X 克」）检测兜底。

## 7. 评审高频问题 Q&A（持续追加）

**Q：这和市面识药 App 什么区别？**
A：它们多是「识别 + 固定文案」；我们是**智能体**——「瓜蒌皮能和川乌一起用吗」这条链（识别→查档案→查禁忌→双源出证）由问题实时生成，评委可现场设计问题验证。

**Q：数据集版权 / 学术性？**
A：NB-TCM-CHM（宁波大学），CC BY 4.0，DOI 10.17632/2kjmzjyrmd；Dataset2 与数据论文跨域协议一致，方法可复现。

**Q：医疗建议风险？**
A：全程不输出诊断/辨证/剂量/疗效，禁忌是知识展示；页面固定免责声明；五道闸门 + eval_safety 10/10 证明。

**Q：训练集测试集会不会泄漏？**
A：Dataset2 是药房实拍手机图（不同拍摄环境），训练/验证完全不接触；跨域 top-1 85.75% 是**降了** 8 个点的——有真实泛化评估的数字，不是刷出来的。

**Q：为什么不用更大的模型（如 ResNet/大模型识图）？**
A：① 细分类本地 93.8% 够用；② 断网场景（演示第 6 步）必须离线；③ 真正难的是「域外」——已用 VLM 互补。成本、离线、精度三维取舍。

**Q：系统怎么跑起来的（部署形态）？**
A：Flask 后端（PyInstaller onedir）+ Vue3/Electron 桌面版：主进程 spawn 后端 stdout 动态端口握手 `HERB_READY_PORT`，同源零 CORS；开发/演示也可纯浏览器连 localhost。

**Q：二期做了什么 vs 一期？**
A：P0 知识底座（22→64 味 + schema v2 + 台账）+ P1 混合检索（20/20）+ P2 智能体侧（六子 Agent/Router/五道闸门/证据链/安全 10/10）+ V2-A6 VLM 二通道（评测校准口径）。一期是"能跑"，二期是"跑得对、说得清、敢给证据"。

## 8. 工程亮点（加分项，随时可讲）

- **页面 0 外部请求**：d3.v7 本地 vendor、matplotlib 本地中文字体（Microsoft YaHei）→ 答辩教室离线可用；
- **断网全链路 fail-soft**：识别/图谱/对话三级降级，仅对话区友好提示；
- **SSE 流式时间轴**：工具逐个触发实时可见（`tool` 事件带 `agent` 徽章），评委看到的是"智能体在思考"；
- **PyInstaller 1114 雷及修复**：conda 环境旧版 VC++ 运行时（vcruntime 14.27）被收进 `_internal`，DLL 搜索顺序抢在 System32 前 → exe `import torch` WinError 1114；`RUNTIME_EXCLUDE` 过滤（依赖系统 14.51+ 运行时）——**改 spec 不要移除过滤**；
- **打包红线**：出包走 `C:\herbal_stage` 英文路径（项目路径含中文，PyInstaller/NSIS 有缺陷）；PyInstaller 必须 `D:\CondaEnv\task\python.exe -m`；
- **Windows 雷区纪律**：`import torch` 必须先于 matplotlib/scipy（c10.dll 加载顺序）；裸 `python` 是损坏的 base 环境 → 全部 `conda run -n task`；
- **自研更可控**：检索（numpy 60 行）、ReAct 循环、图可视化（D3 手写）——每个子系统都敢当场讲原理；
- **上下文统计状态栏**（2026-08-29）：对话栏实时展示 `轮·步 | LLM 时间 · 工具时间 | 平均响应 · tok/s | 缓存命中率 | 输入·输出 tok`——复用 DeepSeek 非流式响应自带 `usage`（含 `prompt_cache_hit/miss_tokens`），逐轮逐工具增量 push；「首 token」类指标需流式化才能测，故口径为「平均响应」，**保持非流式零风险**。实测数据（真实调用）：单轮 `turns=1 · llm 2.67s · 输入 1237 · 输出 220 tok · 缓存命中 93.1%`；跨轮累计 `turns=3 · tokens_in 4615 · 缓存命中 86%`；「新会话」一键重置（`POST /api/session/reset`）。可讲点：**成本与上下文可视化**（缓存命中率↔费用直接挂钩，93% ≈ 7% 的新 token 付费）+ **增量推送的 SSE 协议扩展**（向后兼容，旧前端忽略未知事件类型）。
- **对话记录持久化 + 上传并入聊天输入框**（2026-08-29）：
  - 持久化三层：路由切页不丢（Vue `KeepAlive` 保活 HomeView）+ 服务端会话落盘（`sessions.json` 与 .env 同目录，**原子写 tmp+replace、损坏 fail-soft 自愈**——实测写坏 JSON 后正常启动、首次上传自动重建；`last_active` 淘汰 + 结构校检丢弃非法条目）+ 前端 `localStorage` 存显示层（units/统计，时间轴恢复带 `reactive([])` 包装踩坑，blob 临时图跨重启丢弃、`/uploads` server URL 正常保留）；
  - **重启后指代消解实测**（真实 LLM）：上传纯色图被 VLM 判非药材 → 问「这是什么药材」→ 杀进程重启 → 问「我刚才问了什么」→ 模型准确复述「《这是什么药材》+ 图片判定非中药饮片 + 补拍建议」——messages 完整从磁盘恢复进提示词，无 400（DeepSeek 400 的修复紧跟 tool 回复规则已在历史消毒兜底）；
  - **图片上传并入聊天框**（📎+拖拽，选图待发预览 → 点发送才上传识别 → 图片进聊天流）：`/uploads/<client_id>/<文件>` 新增防穿越静态路由（白名单正则 + `is_relative_to` 双保险——顺手修复 `/upload` 的 client_id 目录穿越隐患）、`image_url` 字段让图片消息用 server URL 持久显示；上传清理策略改为**保留最近 5 张**（原来"清空该 client_id 全部旧图"会让历史消息 404；清理逻辑必须放**保存后**，放在保存前实际会留 6 张——自查发现并修复）；消息内图片 `safeImage` 前缀白名单防 XSS、加载失败显示「图片已清理」占位；
  - UX 拍板口径：**点发送才识别**（选图预览不触发上传）+ **识别结果保留左侧面板**（Top-3/档案/补拍建议/VLM 徽章齐全）——识别卡细节不塞进聊天流，答辩演示信息全。
- **对话区四连 bug 修复 + 卡死防御工程化**（2026-08-29，真实用户实测反馈）：
  - **① 图片发送后消失**：根因=消息内图片 `safeImage` 前缀白名单只放行 `http`/`blob:`，漏掉 server 相对路由 `/uploads/...`（上传成功替换 blob 后即白屏）→ 补白名单。同类教训：**前端任何资源白名单要覆盖「本服务相对路径」这一类**；
  - **② 图+文「这个可以和谁配药时」→ LLM 2s 后无工具链、无输出、不可停**：**后端全链路复现 100% 正常**（4 轮 LLM + 5 工具调用 + answer 正常到达）——卡死不在正常链路，根因是 **DeepSeek 挂起窗口（网络抖动/60s 超时内）无任何 SSE 帧、前端无取消手段**，用户视角 =「卡死」。防御性修复三件套：前端**停止按钮**（AbortController 中止 fetch，服务端 GeneratorExit + 两遍循环保证历史完整）+ **「处理中」指示**（uploading/streaming 全程可见，含上传识别与 LLM 间隙）+ 后端 `generate()` **非预期异常兜底**（except Exception → 必出 error 帧，杜绝「流静默掐断→无输出卡死」）；
  - **③ 两个卡片独立内滚**：`body` 固定 `100vh + overflow:hidden`（页面永不滚）→ `main` `min-height:0 + grid-template-rows: minmax(0,1fr) + overflow:hidden`（行高=视口剩余，不允许撑破）→ `.card` `min-height:0 + overflow:hidden`，左卡 `.result-card` 整卡 `overflow-y:auto`，右卡 chat-body `flex:1 + min-height:0` 内滚（**flex item 必须 min-height:0 才收缩**——经典雷）；窄屏（<900px）恢复整页滚动。⚠️ **二修根因（首版失效）**：flex 加在 `body` 上是死的——body 唯一子元素是 `#app`（index.html 挂载点），而 `header/main/footer` 的父级是 `#app`；正确做法 `#app { height:100%; display:flex; flex-direction:column }` 作为高度链的根，`main/.graph-wrap/.settings-wrap` 各自 `flex:1 + min-height:0` 收缩、内部滚动（图谱/设置页同步受益：整站不再整页滚动）；
  - **④ Ctrl+V 粘贴图片**：`.chat-zone` 加 `@paste` 处理（剪贴板带图片文件时 `preventDefault` 走 pickFile，当附件不当文本）。
- **历史会话管理（多会话）+ 工具耗时口径修正**（2026-08-29，用户实测三问）：
  - **多会话**：会话 = 服务端 `client_id`（sessions.json 本来就按 id 落盘，零迁移成本）——前端会话索引 `herb_agent_sessions`（标题=首条用户消息截 20 字、最近活动排序）+ 每会话显示层分键 `herb_agent_units_<id>`；UI=对话区顶部**会话栏**（下拉切换 / ＋新会话 / 🗑 删除带 confirm）；后端补 `GET /api/sessions`（列表，title 跳过系统注入取首条用户消息）+ `DELETE /api/sessions/<id>`；旧单会话 localStorage 键一次性自动迁移；启动时与 `/api/sessions` 合并（后端恢复的会话补进本地索引）。**可讲点**：多会话是「按 id 分片」而非「另建表」——识别上下文/统计/上传文件天然按会话隔离（`current_herb`/`stats`/`uploads/<client_id>/` 全链路复用同一把钥匙）；

- **「新上传≠旧图片」语境治理**（2026-08-29，用户实测出 bug 后深挖）：先传猫图被拒、再传山楂问「这是啥」→ 模型照抄**自己历史里的旧拒识回复**（左卡山楂 1.0 正确、聊天答猫科动物）。根因：模型对自身历史回复的**自我一致性偏见 > system 注记**；反向场景还出现**句式模板填空**（照抄上轮「识别结果为 X → 查档案」结构，编造「当前识别上下文=枸杞子」并真调工具）。修复两层：提示词层（注记加新旧图片身份区隔+硬指令；实测单独软约束不够）+ **数据层硬修复**（`_reset_messages_for_new_upload`：新上传即把消息历史整体切除、只留底座 prompt——**过期结论要删数据而不是说服模型**）。验证：双向 ×2 轮全过、同图多轮追问与重启指代消解不回归。**答辩可讲**：这是「智能体上下文工程」的活教材——提示词权威性有上限，语境冲突的根治手段在数据层。
- **对话区答案打字机**（2026-08-30）：答案文字**逐字输出**（纯前端，`ChatMessage.vue` 打字机 + 步长自适应 ≈2.4s 封顶，播完无缝切 markdown 渲染，证据链/拒识标签在播完后出现保持「讲完再引用」节奏；点击文字立即显示全文；历史消息恢复不重播）。**选型口径**：不改后端——`stream: False` 时答案是循环末单事件整段到达，真流式要动 ReAct 核心（答辩核心组件）且视觉等价；**答辩可讲**：工具链「逐条弹出」+ 答案「逐字输出」双进度呈现 = 让评审肉眼看到推理链生成过程。

## 11. 讲解子 Agent（STUDY，2026-08-30）

面向中草药专业学生/学徒的**课文式讲解**功能（对话式，复用 SSE 对话轴 + 时间轴徽章 + 证据链）：

## 13. 易混淆饮片鉴别闭环（2026-08-31）

需求来源：用户「根据《易混淆中药饮片鉴别汇总》增添数据库，把如何区分搞上去，与鉴别 agent 绑定——识别出现其中之一时触发并进行细节提问」。§12 的相似对数据是它的数据地基，本节是把「被动对比」升级为「主动引导 + 大模型裁决」的完整闭环。

- **独立鉴别资料库**：`kg/data/similar_guide.json`（17 条两两对，来源=用户提供的《易混淆中药饮片鉴别汇总》教材汇编，**B 档**标签，非药典原文——白名单外药材**不建档案**，MD 只当「问什么」的内容源，绕开 20+ 味新档案人工核对红线）。每组含：来源差异（基原/产地）、**如何区分**（dim 维度对照：形状/颜色/质地/气味/断面/尝味，按『一看二摸三闻四尝』组织）、药效差异（B 档，知识展示不指导用药）。三黄（黄芩/黄连/黄柏）拆 3 条两两，触发时连通聚簇自动重组。
- **触发口径（拍板）**：**两成员都 ∈ 识别 Top-3 才触发**（代码只判同现，是否真正模糊交给模型——LLM 主裁决红线）。触发面 = 图谱互录 21 对 ∪ guide 17 对 ∩ 20 分类类别 ≈13 对（桃仁/苦杏仁/川楝子、砂仁/豆蔻/草豆蔻、枸杞子/五味子、连翘/栀子、山楂/金樱子、乌梅/山茱萸、小茴香/地肤子、覆盆子/五味子 等）。识别成功响应带 `sim_pair`，前端 system-note 提示「可问『这是什么？』」。
- **两模式工具（disambiguate_similar，鉴别 Agent 第 3 工具）**：① 用户无特征 → **提问清单**（维度对照表，逐项询问，不强答）；② 用户给特征 → **研判材料**（对照 + 档案节选 + B 档功效差异 + 核对状态）→ 结论等级（**可判定/部分信息/需人工**）+ 依据由大模型综合给出。代码只组织材料、**不评分不裁决**。
- **上下文注入**：`disambig_ctx` 走独立 system 注记【相似对鉴别】（`_set_disambig_context` 前缀原位替换，稳定前缀红线安全），4 条硬规则——① 无特征先取提问清单逐项问；② 有特征立即传 desc 研判；③ 无关问题正常回答；④ **优先于【当前识别上下文】**（防模型拿识别结果直接下结论——识别结果只是候选，不是答案）。
- **路由**：`classify_agent` 新分支——disambig 激活且非安全/方剂/讲解关键词 → 鉴别（位于学习分支前：『不是X是Y』『这是什么』都是鉴别流程的一部分）。
- **实测（答辩可报）**：`eval_disambiguate.py` **27/27**——离线 22（资料库 17 对、同现语义、连通聚簇、别名归一、两模式断言）+ Router 6 + LLM 端到端两轮 5（t1 取提问清单 → t2 传 desc 研判、结论等级在答案中）；validate --strict 0/0（guide 17 对接入）；**回归全绿**：eval_safety 10/10、eval_teach --llm 31/31、eval_rag 20/20、npm typecheck/build。
- **顺手修复**：`core.run()` 缺 `upload_ctx` 透传（stream_run 有而 run 没有，拒识上传追问注记丢失）——随 disambig_ctx 一并补上。
- **答辩话术**：『识别模型只会给候选，**谁在候选里做最终裁决？是鉴别 Agent 引导用户用可观察特征逐项确认，由大模型综合档案与教材对照下结论**——这是"多模态交互"在鉴别场景的落点：视觉给候选、文本引导确认、知识图谱供依据。』
